1 · Install & run

One line. Asks where to install, builds a private Python venv (nothing global), adds the skill to Claude Code or Codex (auto-detected), and starts the bridge.

curl -fsSL …/install.sh | sh

macOS / Linux. Needs python3, curl, unzip.

Runs the bridge in a named container. WebRTC needs a pinned, published UDP port; the env vars make the install fully non-interactive. It detects Claude Code / Codex and installs the skill in the container.

docker run …

Refresh / update (re-pull the server & skill, restart the bridge) — re-creates the named container:

docker rm -f …

On Docker Desktop (Mac/Windows), WebRTC needs TURN — UDP isn't forwarded reliably. This variant runs a coturn relay in the container (TCP only); then tick Relay through TURN in step 2:

docker run …

For same-machine, Local device is simpler than any of these. Use your host’s LAN IP instead of 127.0.0.1 if the browser is on another machine; --network host works on Linux only.

Bridge running on this computer? Connect directly — no copy-paste. Best choice when the bridge is on the same Mac (incl. Docker Desktop), since it rides the reliable TCP port — WebRTC needs UDP, which Docker Desktop doesn't forward well.
