Two independent over-eager gates were converting glyphs that Slides can render as editable text into rasterised images and fragmenting flex rows. First, the emoji-rasterisation classifier in `convert-pptx-io.ts:145` treated the entire `U+2600–U+27BF` range as pictographs (`return true`), so Miscellaneous-Symbols glyphs like ⚙ (U+2699), ⚠ (U+26A0) and ⚡ (U+26A1) — which are `Emoji_Presentation=No` per Unicode and have reliable monochrome coverage in Slides' font stack — were being rendered as PNG icons instead of text (slide_07: "Why are bottom icons rendered? … can't we use fonts in output?"); the fix narrows the rasterise range to just the Dingbats block `U+2700–U+27BF` so U+2600–U+26FF now stay as editable text. Second, the rich-text-collapse guard in `extract-dom.ts:2513` (`hasInlineSpacingChild`) blocked collapsing any flex row containing a child with `marginRight > 2px`, which forced slide_15's `.line` code rows (whose `.line-num` span carries `margin-right:16px`) into one-text-box-per-span fragmentation and dropped the inter-span whitespace ("curl-XPOST" glued together); since `getTextRuns()` already converts a child's marginRight/marginLeft into injected space runs (~`extract-dom.ts:1333`), the marginRight test was redundant and harmful, so it was removed, leaving only the `letterSpacing !== 0` test — which still excludes slide_16's `.half-header` (`.half-label` has `letter-spacing:2px`) so that flex-header valign fix stays intact.
