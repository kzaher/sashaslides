Root cause: on hosts that carry a symmetric blur-only box-shadow glow (`0 0 Bpx color`, offsetX/offsetY = 0, blur > 0) *in addition to* a spread-only ring, the browser paints the glow as a soft outer circle reaching border-box + blur — larger than the spread ring — but Google Slides renders that same low-alpha OOXML outer-shadow far too tightly, collapsing it inward to roughly the spread-ring radius; the result reads as "outer circle too small," when in fact the spread ring geometry (84px host / 72px bubble) was already correct and it is the glow that renders wrong. Fix (all in `renderer/html2slides/extract-dom.ts`): in the shadow-ring emit block I detect that symmetric blur-only glow (`renderer/html2slides/extract-dom.ts:1731`) and, before the spread rings are pushed so it sits behind them, materialize it as an extra faint outer halo disc — a rounded rect sized to border-box + blur with `borderRadius = s.borderRadius + blur`, filled with the glow color at `fillAlpha = glow.alpha * 0.5 * opA` (halved so a solid disc stays fainter than the spread band, since the real glow fades outward from its peak) (`renderer/html2slides/extract-dom.ts:1732-1750`), and set a `glowHandled` flag (`renderer/html2slides/extract-dom.ts:1730`, set at `:1749`). To avoid double-darkening, the element's own OOXML drop-shadow is then suppressed when the glow was materialized this way — `boxShadow: glowHandled ? null : s.boxShadow` (`renderer/html2slides/extract-dom.ts:1783`). Non-glow shadows and elements without a spread ring are untouched.
