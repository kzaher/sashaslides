The `.metric-pill` on slide_19 is a single visual line made of two inline children (a bold value span + a small label span, ≈187.6px wide), whose true glyph width equals its content box (≈187.2px) to the pixel. The text-fitting path in `extract-dom.ts` insets the label into the content box (subtracting left+right padding) whenever `safeToInset` is true, which left zero wrap slack; under Google Slides' slightly wider glyph metrics the last label word overflowed and wrapped ("Avg. Time to / Purchase"). Two things conspired: the raw `lineRects` count read the two same-top child rects as "multi-line" (forcing the inset), and for a center-aligned element with symmetric padding the content-box inset is geometrically pointless — centering glyphs in the content box lands them at the same x as centering in the border box, so the inset only discards padding that could serve as wrap headroom. Fix (`renderer/html2slides/extract-dom.ts:2848-2876`): compute a `visualLineCount` by clustering `lineRects` by top edge within half a line-height (`:2851-2857`) so multi-child single lines are counted as one; add a `centeredSymmetricSingleLine` gate (`:2869-2870`) for `effectiveAlign === "center"` with `|padL−padR| < 3` and `visualLineCount === 1`; and suppress the inset for that case via `safeToInset = !centeredSymmetricSingleLine && (…)` (`:2876`), keeping the full border box (padding as slack) with the visible center unchanged. The gate is narrow — genuine centered multi-line blocks (`visualLineCount > 1`) still inset and wrap inside their content box — so no other slide is affected.
