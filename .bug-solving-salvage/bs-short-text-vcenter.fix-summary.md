Root cause: pptxgenjs 4.0.1 exposes no per-bullet colour option, so every native `<a:buChar>` marker inherits the paragraph's text colour; CSS lists that colour their marker independently (`li::before` glyph/dot bullets — slide_11 SWOT, slide_30 Key Priorities) were therefore forced off the native list onto a glyph-prefix fallback (a literal "•  " text run + `<a:buNone/>`), which imported into Google Slides as flat text rather than a real, editable coloured bullet list. The fix keeps those lists native and back-fills the colour via a zip post-patch: in `buildPptx` the native-bullet gate was widened to admit coloured `list-style:none` lists (`convert-pptx-lib.ts:2193`), the per-item hex colours are collected in document order (`convert-pptx-lib.ts:2199`) and carried out on the textbox `objectName` as `BUCLR:rrggbb,…` (`convert-pptx-lib.ts:2320`); a new `injectBulletColorsIntoZip` (`convert-pptx-lib.ts:3294`) then finds each tagged `<p:sp>` and inserts `<a:buClr><a:srgbClr val="RRGGBB"/></a:buClr>` immediately before each paragraph's `<a:buSzPct>` (the valid OOXML order buClr → buSzPct → buChar), wired into both the file-based path via a new `injectBulletColors` step (`convert-pptx-io.ts:255`, called at `convert-pptx-io.ts:392`) and the in-memory build (`buildPptxInMemory`). Note: this working tree contains the colored-glyph-bullet change, not the short-text-vcenter letter-badge inset outlined in `analysis.md` — `isNumericCentered` (`convert-pptx-lib.ts:530`) is still numeric-only and the `emitPseudoText` left-pin guard (`extract-dom.ts:2044`) is unchanged, so the vcenter cluster's planned edits are not applied here.
