A thin (few-px) top-accent stripe drawn by a card's `::before` and clipped by the parent's rounded `overflow:hidden` corners was not reproducible as a single native shape: a `round2SameRect` emitted at the stripe's own ~3px-tall bounds clamps its corner radius to `min(w,h)/2 ≈ 1.5px`, so the accent rendered nearly square and overshot the card's ~12px curve, and a prior round "fixed" this by dropping the stripe outright (a `console.warn` + `continue`), which lost the accent entirely — the regression the user flagged on slide_14 ("there should be an element which can present this cut"). The fix in `renderer/html2slides/extract-dom.ts:1982-2050` replaces the drop with a two-shape sandwich emitted at the parent's *padding-box* (full interior height, so the corner radius is real rather than clamped by the 3px stripe): (1) an OUTER accent-filled `rect` using the parent's top corner radii shrunk by the adjacent parent border widths (`extract-dom.ts:2013`) — the rounded-top element that "presents the cut" — and (2) an INNER parent-fill `rect` inset down from the OUTER's top by the stripe height, with its top radii reduced by `stripeH` and bottom radii kept, so it covers everything below the band and leaves only the rounded-top few-px accent visible (`extract-dom.ts:2028`). Shrinking every radius by the adjacent parent border widths keeps both overlays strictly inside the border ring so the parent's own roundRect perimeter still paints its gray/accent edge.
