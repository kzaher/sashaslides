## General principles (apply broadly)

* **Prefer programmatic access over UI automation.** Always ask first: is there an API, a file-based approach, or a native feature that avoids clicking through a UI? Reach for UI automation only when no other path exists.
* **Fail fast, not slow.** CDP operations and DOM interactions are near-instant. If a step doesn't respond in 1–2 seconds, it's stuck — poll with a short budget (e.g., 100 ms intervals, 2 s max) and fail to diagnose rather than blindly waiting 30–45 s. Timeouts should be seconds, not tens of seconds.
* **Poll for observable state, don't sleep.** Instead of `await sleep(5000)`, poll the DOM for the condition that proves the action succeeded (`dialog closed`, `slide count increased`, etc.). Break out as soon as the condition is met.
* **Verify after every destructive action.** Before deleting slides / files / records, count what's there. After deleting, count again and confirm only the intended items were removed. Destructive loops without per-iteration verification will over-delete when an assumption is off by one.
* **Delegate code-writing to smaller models (haiku) when orchestrating.** The main model only needs to read final results (screenshots, counts, error output) and make the next high-level decision. Write a self-contained prompt with the exact task, running instructions, bash timeout, and required report format.
* **Brief sub-agents with hard runtime budgets.** Every delegated script gets a "total runtime must be under N seconds" constraint and a corresponding `Bash` timeout. Runaway scripts are a diagnosis, not a failure mode to tolerate.
* **Sub-agents need exact tab/target identifiers.** When delegating CDP work, give the tab URL substring (e.g., `1xegFC0RQiZd-WaRogVOfSHVqmOFUVPbHUsOHSzPKUUY`, not just `1xegFC0RQiZd`) so the agent can't match a broken/duplicate tab. Sub-agents will happily create new tabs with truncated URLs that 404.
* **Screenshots beat text reports for UI state verification.** When a sub-agent says "the import succeeded," look at the screenshot yourself. Don't trust its interpretation — it may be reading DOM counts from a virtualized list or a hidden overlay.

## Google Slides / Chrome DevTools Protocol specifics

* **REST API (`slides.googleapis.com`) — only the COOKIE/SAPISIDHASH/`gapi.client` paths are blocked** (400/401); the **OAuth2 path WORKS**. `record-rendering-lib.ts` builds `google.slides({version:"v1", auth})` from `/workspaces/sashaslides/.auth/google_oauth.json` + `tokens.json` and successfully calls `presentations.get` (that's how thumbnails are scraped). So you CAN read exact geometry from the devcontainer — see `e2e/api-table-probe.ts`: `presentations.get` returns each table's `tableRows[].rowHeight` / `tableColumns[].columnWidth` (EMU) + element `transform`/`size` = Google's exact computed grid, NO pixel/thumbnail quantization. (`batchUpdate` writes are likely available on the same token — verify before relying on an API "postfix".) **Prefer the API over pngjs pixel-measuring a thumbnail** whenever you need grid geometry (col widths/origin are exact: col = 1.0008·spec, RMSE 0.66px). CAVEAT: the API `rowHeight` is the STORED grid height, which differs from the VISIBLE rasterised fill — they agree ~1px for content-fitting rows but the fill renders ~0.2·font taller (line-box) and multi-line reflows PAST the stored magnitude (e.g. stored 53.8px → visible 64.8px). So: API grid for native-cell geometry; pixel fill for corner-MASK overlay alignment.
* **Programmatic path that works:** generate `.pptx` with `pptxgenjs`, upload via Drive web UI using `DOM.setFileInputFiles` to inject the file into Drive's hidden file input, then open `https://docs.google.com/presentation/d/{fileId}/edit`. See `presentations/scripts/generate-pptx.ts` + `upload-pptx-to-slides.ts` + `find-and-open-pptx.ts`.
* **Migrating slides between presentations:** use Slides' native **`File > Import slides`** feature. This is the only clean way to move slides with styles/backgrounds/images between Google Slides files from inside the devcontainer.
* **Google Slides React widgets ignore `Input.dispatchMouseEvent`** for many custom buttons (e.g., "Select all slides", "Import slides" in the Import dialog). Use **`Runtime.evaluate` to dispatch full pointer-event sequences** via JavaScript instead:
  ```js
  const opts = { bubbles: true, cancelable: true, clientX, clientY, pointerType: 'mouse', button: 0, pointerId: 1 };
  el.dispatchEvent(new PointerEvent('pointerdown', opts));
  el.dispatchEvent(new MouseEvent('mousedown', opts));
  el.dispatchEvent(new PointerEvent('pointerup', opts));
  el.dispatchEvent(new MouseEvent('mouseup', opts));
  el.dispatchEvent(new MouseEvent('click', opts));
  el.click();
  ```
* **Text entry in Slides placeholders:** Enter enters the placeholder for editing, Tab cycles to the next placeholder, Escape exits. Double-click via mouse events is unreliable. `Input.insertText` works for the actual text; **never** type a font name into the toolbar font picker — it ends up as text content in the slide.
* **Filmstrip uses virtualization.** `document.querySelectorAll('.punch-filmstrip-thumbnail').length` returns only rendered thumbnails. To get a true count, first set `.punch-filmstrip-scroll.scrollTop = 99999` to force-render all of them.
* **`Ctrl+A` in the main edit area selects objects on the current slide, not all slides.** To select all slides, click in the filmstrip first. `Ctrl+A` inside a Picker dialog selects page text, not dialog items — use per-thumbnail `.click()` or a native "Select all" button via PointerEvent.
* **Filename-like menu items include keyboard shortcut hints.** `File > Import slides` appears in the DOM as textContent `"Import slides(Z)"` — match with `startsWith('Import slides')`, not `=== 'Import slides'`.

## Whiteboard / visual style

* **Google Fonts "Caveat" and "Patrick Hand"** render natively in Google Slides (no font upload needed). Good for handwriting / whiteboard looks.
* **Hand-drawn icons via rough.js:** render SVG in Chrome (via a local HTML file opened with CDP), then screenshot each icon with `Page.captureScreenshot` using a clip region. `rough.svg(svg)` methods return drawables that must be **manually `appendChild`'d** to the SVG — wrap them in an auto-append shim.
* **Use a real whiteboard photo as background**, not CSS-synthesized shapes. `pptxgenjs` supports `{ image: { path, x, y, w, h } }` in slide masters. Convert webp→png with ImageMagick (`convert in.webp -resize 1920x1080\! out.png`) since pptxgenjs prefers PNG.
* **Hand-drawn lines and tables**: plain `slide.addShape("line")` and `slide.addTable()` look too clean. Pre-render them as PNGs via rough.js (one underline per slide, one table per slide with a table) and embed with `slide.addImage()`. See `presentations/scripts/render-assets.ts`.
* **Safe writing area inside a whiteboard frame**: use `SAFE_X=0.9, SAFE_Y=0.7, SAFE_W=13.33-2*0.9, SAFE_H=7.5-0.7-1.2` (bottom margin leaves room for the marker tray). All content should fit inside this to stay visible on the whiteboard surface.
* **Graph rendering library**: `presentation-templates/whiteboard/whiteboard-graphs.js` exposes `WhiteboardGraphs` with `barChart`, `lineChart`, `pieChart`, `flowDiagram`, `pillars`, `hubSpoke`, `roadmap`, `axes` — all via rough.js. Include with `<script src="https://cdn.jsdelivr.net/npm/roughjs@4.6.6/bundled/rough.js"></script>` then the lib.

## Presentation templates as skills

* **Every presentation template is its own skill.** `presentation-templates/<name>/` holds all template assets (backgrounds, graph libraries, icons). `.claude/skills/<name>-presentation.md` + `.sh` is the user-invocable entry point. The `.sh` runs the pipeline: render assets → generate .pptx → upload to Drive → (optional) import into existing presentation.
* Template skill naming: `<template-name>-presentation` (e.g., `whiteboard-presentation`).
* **Edit-and-redraw workflow for graphs:** graph configs live in a JSON file (e.g., `presentations/1/graphs.json`); each graph image embeds `altText: "graph:<name>"` so users can identify them via right-click → Alt text in Slides. A `/redraw-graphs` skill re-renders assets → regenerates .pptx → uploads → re-imports into the target presentation. Round-trip: ~20s.

## Whiteboard companion-slide architecture (source/render pairs)

* **The whiteboard generator emits paired slides, not single slides.** For every slide whose first speaker-note line is `whiteboard=1`, `generate-pptx.ts` writes:
  1. a **source slide** (filmstrip pos N, `slide.hidden = true`) holding native editable primitives — real `addText`, `addTable`, `addChart('bar'|'line'|'pie')`, and `addShape` compositions for diagram showcases (flow / pillars / hub-spoke / roadmap), plus `addShape('line')` for title underlines and section dividers.
  2. a **render slide** (filmstrip pos N+1, visible) holding the same text plus rough.js PNG overlays for tables / charts / diagrams / underlines at the same bounds.
  This is what audiences see; the source is hidden but kept for editing.
* Slides without `whiteboard=1` get a single plain slide on a default theme — no whiteboard background, no overlays.
* **Pair linkage** lives in speaker notes. Both slides in a pair end with the sentinel line `|This is autogenerated, please don't touch={...json...}` containing `{role:"source"|"render", pairId, kind, overlays?}`. `pairId` is a deterministic hash of slide index + title so re-runs of the generator preserve pair identity. Future restyle tooling looks up the partner by `pairId`.
* **`slide.hidden = true` on pptxgenjs 4.0.1** writes `show="0"` on the slide XML (verified at `node_modules/pptxgenjs/dist/pptxgen.es.js:6496`). Google Slides imports that as native **Skip slide** — the slide stays in the filmstrip but is omitted from presentation mode.
* **Per-slide unique underlines.** The previous "one shared `underline.png` reused on every slide" approach (a) made every title look identical, and (b) at the small display height (~0.3″) the rough.js wobble at `roughness:4, bowing:3` looks like a clipped scribble. Replacement: render at flatter aspect (`2400x48`) with `roughness:1.8, bowing:1.2, strokeWidth:8/7`, and emit **6 blue variants** + **3 red variants** with different seeds. `generate-pptx.ts` cycles a `contentSlideCounter % 6` (and `sectionCounter % 3` for red dividers) so consecutive titles never share a drawing.
* **Native shape library used by source slides:** `addShape('line', {h:0, line:{endArrowType:'triangle'}})` for arrows, `addShape('roundRect')` for flow/roadmap nodes, `addShape('rect')` for pillars, `addShape('ellipse')` for hub & spoke. All are individually selectable and editable in Slides.
* **pptxgenjs 4.0.1 capabilities verified for this design:** `slide.hidden`, `addChart` (BAR/LINE/PIE), `addShape` arrow shapes (`rightArrow`, `leftArrow`, `line` with `endArrowType`), `addNotes`, `addTable` with per-cell formatting. ChartType strings are lowercase (`'bar'`, `'line'`, `'pie'`).
* **Hand-drawn lines must be fat AND rough.** rough.js `roughness: 2, strokeWidth: 4` is too subtle for big elements — use `roughness: 3.5–4, strokeWidth: 12–14, bowing: 2–3` for things drawn at large display sizes. **Underlines are the exception**: at ~0.3″ display height the wobble dominates, so they need flatter aspect + lower roughness (see above). Always render 2–4× the final display size so roughness stays crisp after Slides rescales.

## html2slides fixtures & regression gating

* **Basic fixtures** live at `analysis/renderer/html2slides/e2e/fixtures-basic/` and cover one feature per slide (rects, borders, gradients, shadows, text, **nested recursive elements, lists, tables with varied borders**). Complex layouts go in `fixtures/`.
* **Never show the user new fixes without running the goldens gate.** Workflow is: `./regen-basics.sh` (regen + diff vs. goldens) → eyeball each `/tmp/sxs/diffs/diff_slide_NN.png` in a **parallel Agent per diff** (ingest the diff image directly, do NOT compare original vs. new side-by-side) → confirm all diffs are intended → hand the user the updated SxS link and let them rate. Full details: `analysis/renderer/html2slides/README.md`.
* **Always analyze rating-UI pictures inside a sub-agent — never directly in the main context.** Images from `/tmp/sxs*/originals/`, `/tmp/sxs*/slides/`, `/tmp/sxs*/diffs/`, and `/tmp/sxs*/annotations/` are large and blow out the main window. Delegate: pass the absolute paths (original, rendered, annotation, diff) plus the user's comment from `ratings.json` to an Agent, and ask for a text-only report (what the user is pointing at, what's different, likely root cause). Then the main context ingests only the concise diagnosis and decides the fix. Never open those PNGs via Read in the orchestrator.
* **Verifying a table/geometry fix: RENDER to Google Slides and pixel-compare — never trust pptx-XML inspection alone.** Repeated bug-solving retries "verified in XML" that shapes landed on the perimeter, then FAILED the visual validator, because Google Slides re-rasterises native `<a:tbl>` cells (cell-fill inset, min-row-height, rounded-nook AA) independently of the XML coords. The reliable loop (Chrome CDP is on :9222): `convert-pptx.ts --only slide_NN.html --no-upload` to sanity-check geometry → then `convert-pptx.ts --only … ` (uploads, prints pres id) → `export-thumbs.ts <presId> <dir>` + `shot-originals.ts` for the Chrome truth → ImageMagick crop the region + pixel-measure transitions with `pngjs` (in root `node_modules`) → delegate the crop to a sub-agent for a calibrated read. **Calibrate crop coords from the rendered image, not from EMU math** — the Slides PNG export does not map linearly from slide-EMU (e.g. a table whose EMU bottom ≈ 0.40·H actually landed at y≈399/900), so scan for the pink/dark/white transitions to locate elements before cropping.
* **`perimBleed` past a table edge fattens a visible cell border.** Bleeding a corner/edge mask outward past the table perimeter to "cover an AA seam" only helps when the perimeter colour differs from the wrapper (dark cell on pink, suppressed-underlay tables). When the perimeter colour IS the intended thin border (`.colored`'s `border:1px #fff`, whose white underlay already reaches the edge), the extra bleed renders the 1px border as ~2.5px of white eating into the wrapper margin — read by users/validators as "corner cell slightly misaligned edge". Gate perimBleed on `extX>0` (the side owns an outer table border) so bordered tables keep it and borderless white-bordered tables land flush.
* **Goldens are user-only.** `e2e/goldens/*.png` may ONLY be written by the user clicking "Good" in the SxS rating UI — that is the sole sanctioned writer. Claude must NEVER `cp`/`mv`/write files into `e2e/goldens/`, never run `check-goldens.ts --bless` (disabled anyway), never promote regenerated thumbs as goldens. If a fix looks right, regen + diff and hand the result back; let the user bless. The sentinel `e2e/goldens/.BLESSED_BY_USER_ONLY` documents this boundary in-tree.

## Google Slides table layout — reverse-engineered model (measured, not guessed)

* **Closed-loop fuzz harness for table geometry:** `e2e/google-table-fuzz.ts` (gen N fuzzed solid-colour tables → render via `record-rendering --mode full` in ONE upload → measure every rendered row/col/origin from the thumbnail) + `google-table-fit.ts` (train/test fit + held-out validation, emits `google-table-model.ts`) + `google-table-report.ts` (markdown data tables → `gtl-report.md`). `record-rendering --slides <csv>` packs all slides into ONE combined pptx → ONE upload → per-slide thumbnails, so ~100 tables = 1 upload (watch the Slides API "Expensive read requests per minute" quota — ~67 thumbs/min before it throttles; split into batches).
* **Measurement technique (pngjs, NOT PIL — PIL isn't installed):** detect a true row boundary as a colour jump in the FULL-WIDTH average profile (text glyphs/col edges cancel); detect columns by per-x MEDIAN hue over the tallest row band, skipping near-black/near-white pixels (text is a vertical minority → median locks onto the fill). **`at(x,y)` needs INTEGER coords** — a fractional `y` from a float band edge reads garbage bytes and silently flattens the signal (round all band edges).
* **THE LAW (validated cross-seed on 701 pts, held-out row RMSE 1.02px R²=0.998, col RMSE 1.31px R²=0.9999, train≈test ⇒ no overfit):** `rendered_row_h = max(spec + 0.72, 1.197·font·lines + 0.98·(2·padY) + 0.51)` and `rendered_col_w = 1.003·spec − 0.10`. The 1.197 line-box factor = CSS `line-height: normal` (≈1.2). **Border width does NOT grow the row** (A/B test: adding it worsened held-out RMSE 1.02→1.51px). Tiny fonts (≤10px) hit an absolute ~13px min row height the linear floor under-predicts (rare). Applied in `convert-pptx-lib.ts` as `predictGoogleRowHeightPx()` driving `ringlessOvershootBottom`.
* **Google honours specified table geometry to ~1px** (origin offset −0.4±0.85px, width +1.8±2.5px, col slope 1.003). **Corollary:** any multi-px corner/edge misfit on a real slide is the converter's OWN overlay math (shape-twice corner masks / shape-render path), NOT Google re-rasterising the table. So a row-height fix is a NO-OP on slides whose rows already exceed the font floor (e.g. slide_17, max font 22 → floor ~27px, rows ~50-90px → MD5-identical render before/after). Diagnose the overlay code for those, don't keep tuning the layout law.

## TypeScript / Node tooling gotchas

* **`pptxgenjs` ESM/CJS interop** needs `(pptxgenModule as any).default || pptxgenModule` — direct `import pptxgen from "pptxgenjs"` hits "not a constructor" under Node 22 ESM.
* **`npx tsx -e "..."` resolves modules from `cwd`**, ignoring `--prefix`. Write scripts to files under the directory that has `node_modules`, then `cd` there and run `npx tsx file.ts`.
* **Background `run_in_background` outputs are truncated.** If a long-running task writes to a log file, poll the file instead of trusting the final notification summary.
* **`claude -p --model haiku` is the cheapest way to call Claude from scripts** in this devcontainer. No ANTHROPIC_API_KEY needed — it uses the current session's auth. Use `--output-format json` to get token counts. Combine with `--dangerously-skip-permissions` for non-interactive runs.
* **`claude -p` fails silently with large stdin prompts** (>10KB). The pipe buffer fills and the process hangs until timeout. Workaround: write prompt to a file, use `claude -p < file.txt`, or use the Agent tool for large generation tasks. Small prompts (<5KB) work fine via pipe.
* **Analysis eval system** lives in `analysis/`. Three prompt candidates for design extraction; `run-eval.ts` orchestrates end-to-end eval. Renderer in `analysis/renderer/` tracks iterations with tokens/time/fidelity metrics.
* **structured-prompting builds with esbuild only (no `tsc` gate) — a misnamed object-literal field silently no-ops.** esbuild strips types without checking them, so passing a property the target type doesn't declare (e.g. `new Session({ …, n: x })` when `SessionInit` actually has `containerId`) compiles clean, drops the property at runtime, and produces a subtle wrong-behaviour bug with NO build error. When adding a field to a constructor/options call, READ the target interface first (or use the LSP) — don't trust a remembered field name. The eslint gate (`no-explicit-any`) does NOT catch this.
* **structured-prompting engine: container-body sessions must carry `containerId`, not just `tipNodeId`.** In `engine.ts`, every `new Session(...)`/`new SessionWithResult(...)` that runs a container's body (`pipe`, `parallelChild`, `try`/`tryAttempt`/`tryFallback` bodies, `combineWith` branch) must pass BOTH `tipNodeId: <containerNodeId>` (chain-after) AND `containerId: <containerNodeId>` (nest-under). `SessionInit.containerId` defaults to `graph.rootId`, so omitting it flattens the whole subtree onto the root — the monitor UI nests by `containerId` (serialized as `n` on the wire) and infers container-vs-leaf from it, so a missing anchor breaks BOTH indentation and per-node status glow at once.
* **`codex exec resume` rejects `--cd`** ("unexpected argument '--cd' found"). A resumed session inherits its recorded cwd (and the spawned process cwd still applies), so pass `--cd` only on a FRESH `codex exec`, never on `resume`. resume DOES accept `--json`, `--output-schema`, `--model`, `-i/--image`, `--skip-git-repo-check`, `--dangerously-bypass-approvals-and-sandbox`.
* **Codex with a ChatGPT account rejects Claude model names** ("The 'opus' model is not supported when using Codex with a ChatGPT account."). The structured-prompting graph injects Claude identifiers (`opus`/`sonnet`/`haiku`) by default; `codex-cli.ts`'s `codexModelArg()` drops Claude-family tokens (omit `--model` → codex account default) while letting a genuine codex model pass through.
* **Long-running engine launches must be `setsid`-detached, not `run_in_background` Bash.** The harness/sandbox reaps tracked background Bash tasks at the turn boundary — that kills the scaffolding, the monitor server, AND any in-flight worker together. Launch with `setsid env … node dist/main-scaffolding.mjs > log 2>&1 < /dev/null & disown` (same as Chrome) so it outlives the turn; poll the log file for completion since a detached process won't send a task-notification. Chrome for convert-pptx must also be running on `:9222` (`google-chrome-stable --headless=new --remote-debugging-port=9222 --no-sandbox --user-data-dir=/tmp/chrome-cdp`) — the devcontainer's instance dies on container restart.
* **bug_solving's post-verdict productization (`upload-and-scrape` → SxS thumbnails) must be NON-FATAL, and the script was inlined.** `upload-and-scrape.ts` (like `record-pptx.sh`) was inlined into `record-rendering.ts` (commit 346965d); `main.ts` step 7 still called the dead path, so a SOLVED attempt (verdict already passed at step 6b) died on the missing script and `tryMultipleTimes` looped a *correct* fix forever. This is how the claude run "failed" while actually solving it. Fix: step 7 now runs `record-rendering.ts --mode full` from the worktree `renderer/`, suffixed `|| true` so a flaky Google upload can't throw away an already-passed fix. RULE: anything that runs AFTER the verdict (uploads, thumbnails, external side-effects) must be best-effort — never let it convert a PASS into a retry. When a bug_solving attempt fails, check WHERE in the chain it threw (`tryAttempt` node error): a step-7 shell failure ≠ a verdict rejection.
* **bug_solving worker must `switchCwd(task.workspace_dir)` or it edits the MAIN repo.** A `Session`'s cwd defaults to `process.cwd()` and `parallelFork` children inherit it, so without an explicit `switchCwd` the worker's codex/claude `--cd` is the scaffolding's main checkout — its edits never land in the per-task worktree, record-after sees nothing, and every task reports `UNSOLVED: no structural differences`. `main.ts`'s parallelFork apply must start each task with `child.switchCwd(task.workspace_dir)`. `switchCwd` is a node kind (mirrors `switchModel`: graph schema + `Session.switchCwd` + engine `case` setting `ctx.cwd`). The engine's per-node git-diff feature is what surfaced this — the captured diff showed only main-repo files.
* **The structured-prompting monitor runs IN-PROCESS — `process.exit()` kills it, even with `persist:true`.** The engine's `persist:true` keeps the monitor server listening after `execute()` returns (the listening socket keeps the event loop alive), but it cannot survive a `process.exit()`. `main-scaffolding.ts` used to `process.exit(1)` on any task failure, tearing down the monitor exactly when you'd want to inspect the failed trace ("engine not accessible" after a failed run). The graph is NOT persisted to disk (`graph.setPersist` is never called) and there's no view-graph tool, so once the process exits the trace is GONE. Fix in place: on failure the scaffolding now keeps the process alive while `engine.monitorUrl` is set (only `exit(1)` when there's no monitor to preserve) — Ctrl-C to stop it. If you need to inspect a failed run, it must still be the SAME process that ran it; re-run to regenerate a live trace.
* **The single canonical SxS rating server is `renderer/html2slides/rating-server.ts`** (run `npx tsx rating-server.ts <results-dir> [--port 3456]`). It is the ONLY rating UI — the old `filtered-rating-server-lib.ts` (a richer Preact variant inside `structured-prompts/`) was deleted during consolidation, and its features were ported into `rating-server.ts`: Pen + **Rect** drawing tools, a hover **Magnifier** loupe, and per-annotation **zoom-crops** (client tracks shapes → `/api/rate` crops original+test per marked region via `zoomCropPng`/`annotationBbox` → rendered as "original vs test" pairs below the slide under `zoom-crops/`). `filtered-rating-server.ts` remains as a thin no-UI launcher (flag-translation → execs rating-server.ts) for bug_solving. Lesson: when "consolidating", port EVERY feature out of the file before deleting it — the lib had magnifier + zoom-crops that a naive delete silently dropped.
* **Run the rating server with a NON-`/tmp` results dir so annotations + zoom-crops survive container restarts.** It writes annotations to `<results-dir>/annotations/` and crops to `<results-dir>/zoom-crops/`; point `<results-dir>` at a persistent path (e.g. `/workspaces/sashaslides/.sxs-complex`) and symlink `/tmp/sxs-complex` → it so bug_solving's `buildSlideTasks` (which reads `/tmp/sxs-complex`) still finds them. The annotation PNG is a USER-drawn artifact — it cannot be regenerated, only re-drawn, so don't let it live only in `/tmp`.
* **Model work-products must live OUTSIDE the gitignored scratch dir to appear in the per-node diff.** bug_solving's `.bug-solving-scratch/` is in `.gitignore` (for the binary pptx/diff artifacts), so `git add -A` skips everything under it — including the worker's `analysis.md`/`fix-summary.md`. Those model docs are written to a separate non-ignored `bug-solving-analysis/` dir (in `workspace-setup.ts` + `main.ts`) so they show in the diff; only script-generated binaries stay in scratch. General rule: if you want a file the worker writes to be reviewable in the diff, don't put it under a gitignored path (and you can't `!`-negate a file inside an ignored directory).
* **git pathspec `(glob)` magic is required to exclude a dir AND its contents at any depth.** A plain `:(exclude)**/node_modules` silently fails inside a worktree (where node_modules is a symlink but tracked-as-a-dir at HEAD): a non-glob `**` does NOT cross `/`, and matching the dir name alone does not cover files under it. Use all three: `:(exclude)node_modules`, `:(exclude,glob)**/node_modules`, `:(exclude,glob)**/node_modules/**`. Verify against a real worktree, not the main repo — in main, node_modules is unchanged so a broken exclude looks like it works.
* **A glob pathspec literal in a JS/TS block comment breaks the parser.** Writing `**`+`/`+`node_modules`+`/`+`**` inside a `/** … */` comment contains a `*`+`/` that closes the comment early → "Parsing error: ';' expected". Use line comments (`//`) or prose ("double-star") when documenting glob pathspecs.
